Recall vs Latency

The fundamental tradeoff in vector search

The Core Concept

This demo uses 100,000 random vectors (128 dimensions, HNSW with m=8) to show how approximate nearest neighbor search works.

Exact search = checks every vector = 100% recall, but slow
Approximate search (HNSW) = navigates a graph = fast, but may miss results

The ef (exploration factor) controls how many nodes HNSW explores. Higher ef = closer to exact results, but slower.

Why batch? With per-query latency measurements, network overhead and system noise dominate the signal. By running many queries and summing the time, we amplify the real computational cost differences into clearly measurable values.

Why random vectors? Random 128D vectors spread uniformly across the space, making nearest-neighbor search genuinely difficult for HNSW. Real-world data is often clustered, which makes HNSW's job easier and recall higher.
